## Original model assumptions

The independent coordinate system uses +X east, +Z south, +Y up. A 105 × 68 m pitch is a modeling convention, not a survey claim. Stand frontage, setbacks, rises, tiers, roof height, entries, and eye heights are authored approximations in `src/stadium/layout.ts` and `src/stadium/model.ts`. The South terrace is intentionally unassigned; sample bands identify a region for an illustrative camera, not a personal standing allocation. Corner terraces currently provide architectural context without selectable inventory.

All models, materials, pitch lines, and place data are generated by project code. No photo textures, imported models, reference artwork, proprietary fonts, logos, or ZIP contents were used. Runtime library license notices are included in `public/THIRD_PARTY_NOTICES.txt`.

## Photo comparison and sightline limits

Visual comparison used the existing curated aerial and interior panorama, plus `interior-south-view.jpg` and `interior-stands.jpg`, inspected during this implementation. The high North preview was compared qualitatively with the view toward the South Stand: a broad South end, two side tiers, a rectangular pitch, corner transitions, and overhead trusses. The side previews were compared with the interior photos for the presence of tier fronts, entry openings, roof edges, foreground seats, and rails. The full-roof overview was compared with the aerial reference for the four-sided roof opening and paired yellow corner pylons.

The model deliberately omits exact seating color artwork, lettering, sponsor panels, survey-specific corner slopes, and exact concourse/entry placements. The photographs are not labeled with measured camera coordinates/heights, and event seating configurations differ. These checks support architectural recognition and plausible model viewpoints only. They do **not** calibrate exact venue sightlines or prove an unobstructed view from any real ticketed place. Every preview retains the unverified/illustrative label.

Automated rays test generated camera paths and representative directions toward the pitch centre and both goals. An early test caught a portal cap intersecting an upper-tier near-goal sightline; portal placement was corrected. Physical barriers and roof structure remain visible in previews. No numerical visibility score or verified restricted-view claim is produced.

## Verification performed

- `npm run build`: strict TypeScript and Vite production build pass. The Three.js engine is loaded separately from the shell. Vite reports a roughly 576 kB uncompressed engine chunk (about 144 kB gzip); this is a known bundle warning, not a failed build.
- `npm test`: five meaningful suites pass, covering deterministic hierarchy/IDs and standing semantics, distinct and ascending Low/Middle/High shortcuts in every block, camera-route endpoints, **150 representative flight paths** with full roof, and **225 representative model sightline rays**.
- `npm run test:browser` with local Vite and headless installed Chrome: pointer hover and picking, drag suppression, reset, roof toggle, **12 low/middle/high previews across all four stands**, mini-map direction, keyboard look/zoom, Escape, focus restoration, flight interruption/reselection, reduced motion at load and changed during a flight, and WebGL failure/context loss/retry pass. No uncaught browser errors.
- Responsive checks at **390, 768, 1024, and 1280 px** show no horizontal overflow. Emulated mobile touch buttons complete South-area preview/return. This is not a physical-phone test.
- Original-render screenshots were reviewed for overview/full roof, seated previews, South terrace, and mobile view. Reproducible screenshots are written to ignored `.cache/qa/`, never bundled with production assets.
- A 120-frame continuous-control check measured median **33.3 ms** and p95 **33.4 ms** frame gaps at both 1440 and 390 px in this headless Chrome environment. This is approximately 30 Hz frame cadence, not a claimed 60 fps desktop result or real-device GPU benchmark. Desktop cutaway: 149 draw calls / 524,736 triangles. Compact mobile cutaway: 111 calls / 293,088 triangles. Compact mode omits seat backs while retaining selectable seat positions; pixel ratio is capped. Idle rendering is demand-driven.
- `npm run check` audits working files and the existing staged snapshot against their respective provenance inventories, and scans reachable history. The audit now supports independently staged/unstaged work without requiring replacement of the user's staged registry.

## Reproduce

```sh
npm ci
npm run build
npm test
npm run check
npm run dev -- --host 127.0.0.1 --port 5178 --strictPort
# In another terminal, with Chrome installed:
npm run test:browser
```

`TEST_URL` selects a different running Vite URL. `TEST_BROWSER` selects a Playwright browser channel (default `chrome`). The browser check imports local source modules to project a known place, so run it against Vite development mode. Only the test runner is installed; no browsers are downloaded or included in the app.

Task 9 still owns broader Safari/Firefox/physical-device testing, full screen-reader/contrast checks, sustained performance profiling, and release-wide QA. Venue-grade sightline validation requires licensed position-known photography or survey data. Tasks 7–10 remain open.
